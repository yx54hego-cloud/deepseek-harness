# Agent Note: 手机端会话创建与导航操作

Status: implemented

[English](2026-08-15-mobile-navigation-actions.md) | 中文

## 问题

手机伴侣已经显示导航抽屉和设置入口，但它们的主要操作没有实现。新建会话、工作区发现和设置入口看起来可以点击，却要么没有反应，要么错误地触发“忘记电脑”。工作区分组也共用一个展开槽位，因此抽屉无法表示全部收起的状态。

## 决策

手机载体 allowlist 加入 `session.create` 和 `workspace.list`。点击顶部或抽屉的新建会话后，应用先把当前 Session 解析到 Host 工作区并发送工作区 ID；只有找不到已注册工作区时才回退到当前工作目录。输入框工作区操作复用同一套创建流程，并将所选工作区 ID 传给 Host，因此会在目标工作区创建并打开一个新的空白 Session，而不是尝试迁移当前 Session。持久化创建仍由 Host 负责。

载体还会在 WebSocket 边界隔离请求失败。Host 处理器失败或返回非 JSON 错误响应时，当前请求会收到加密的 RPC 错误，不会再变成未处理的 Promise rejection，进而触发应用的 fail-loud 进程退出。

抽屉执行本地工作区／会话搜索，提供按最近活动或名称排序，并为每个工作区分别保存展开状态。整理操作可以全部展开或收起；增加工作区仍保持禁用，因为工作区注册属于 Web 表层。设置底部入口现在打开原生设置页面，包含通用设置、模型、插件和 Agent 预设四个入口。每个入口目前显示受控的占位说明，因此导航是真实可用的，同时不虚构手机专用配置语义。

手机端现在通过 SecureStore 保存带版本的多个已配对 Host，并在首次读取时迁移之前的单 Host 记录。设置中的设备管理会列出已保存电脑、跨启动保留当前选择，支持切换、移除配对，并可以重新扫描二维码添加设备而不影响已有设备。二维码相机现在放在独立的原生 Modal 中，对话页面保持挂载；关闭 Modal 前会先移除相机预览，避免 SurfaceView 在取消后覆盖对话页面。

## 考虑过的替代方案

- **为这些操作打开 Web UI。** 拒绝，因为手机伴侣是窄范围的原生对话表层，不应暴露浏览器壳层及其更宽的权限。
- **构建第二套手机工作区／会话实现。** 拒绝，因为现有 `ctx.apiProxy` Session API 已经负责持久化创建并拥有正确的工作目录语义。
- **在工作区之间迁移已有 Session。** 拒绝，因为 Workspace 成员关系要求 Session header 的 canonical `cwd` 必须等于工作区路径；修改这个不可变的执行目录会改变核心 Session 语义，并可能使会话的工具上下文失效。
- **为了界面简单继续只允许一个工作区展开。** 拒绝，因为这阻止用户收起所有分组，并让多工作区导航状态依赖一个隐藏槽位。
- **继续只保留一个配对槽位，在扫描新二维码时覆盖旧设备。** 拒绝，因为一部手机可能控制多台 Harness 电脑，配对材料必须能够独立选择和移除。

## 后果

- 新建会话是真实的 Host Session，并绑定到选中的已注册工作区，手机或浏览器可以立即向它发送提示。
- 从输入框选择工作区会在该工作区创建一个新会话；当前会话及其历史保持不变。
- 搜索、排序和展开状态只是本地显示状态，不扩大手机载体权限，也不修改工作区顺序。
- 设置导航已为后续配置工作准备好，同时不会暗示四个占位页面已经能够修改 Host 设置。
- 手机端能力调用失败会被限制在当前 socket 内，并作为 internal RPC 错误返回，不会再通过未处理的 Promise rejection 终止 Host 进程。
- 多个 Host 配对会保存在操作系统安全存储中，当前 Host 按 device id 选择，旧版单 Host 数据会自动迁移。
- 二维码扫描器隔离在原生 Modal 中，并在关闭前移除相机会话，避免黑色相机表面残留在对话布局上。
- Mobile carrier 测试覆盖新的加密 `session.create` 请求，手机类型检查覆盖原生页面与客户端方法的新增内容。
