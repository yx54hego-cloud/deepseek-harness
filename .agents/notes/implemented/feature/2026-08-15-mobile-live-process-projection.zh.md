# Agent Note: 手机端实时过程投影

Status: implemented

[English](2026-08-15-mobile-live-process-projection.md) | 中文

## Problem

手机伴侣虽然已经收到 Web 会话事件流，却只把用户和助手文字投影出来，因此用户在手机上看不到轮次中的上下文注入、思考、工具执行、审批和提问过程。

## Decision

手机伴侣继续使用现有的 `session/event` 传输，并在对话尾部增加可展开的实时过程面板。投影内容包括上下文消息、轮次和步骤边界、推理增量、工具调用与结果、审批请求与结果，以及用户提问请求与结果。手机载体会转发瞬时的审批和提问 mux 帧，并在会话重新加载前将它们合并到同一个投影中。非用户来源的上下文消息不再重复显示为普通聊天气泡。

面板只负责显示，不增加手机端审批或回答问题的控制；普通用户和助手消息仍以持久会话记录为准。

## Alternatives considered

**增加单独的手机活动协议。** 放弃，因为 Web 会话事件流已经携带有序的生命周期和工具事实，新增流会造成顺序和重连漂移。

**把每个过程事件渲染成聊天气泡。** 放弃，因为内部生命周期行会挤占对话空间，导致输入栏难以使用。可展开的尾部面板保留事件顺序，同时不改变持久会话记录。

**只显示一个“正在处理”摘要。** 放弃，因为这会丢失 Web 界面已经展示的具体工具和思考状态。

## Consequences

手机端现在通过现有的认证加密通道跟随 Web 端过程时间线。由于用户要求在可信局域网内显示与 Web 等价的过程，面板可以包含原始上下文、工具参数和工具结果；界面仍对文本视觉高度做了限制，以保持对话可用。手机端仍不能回答 Web 审批或提问，因此这些行目前只读，后续若增加交互需要单独授权和设计。

## Testing

协议投影已覆盖上下文、思考、工具、审批和完成事件。mobile-access 组合测试覆盖审批和提问帧的转发；手机端类型检查、聚焦协议测试与 Host 构建均通过。
