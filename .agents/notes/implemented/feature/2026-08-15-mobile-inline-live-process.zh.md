# Agent Note: 手机端内嵌实时过程

Status: implemented

[English](2026-08-15-mobile-inline-live-process.md) | 中文

## Problem

第一版实时过程界面把 Web 生命周期行放在对话记录下方的独立可展开面板中。这让可见的处理过程与助手回复分离，用户看到的像是完成后的答案后面又跟着一个诊断抽屉。

## Decision

把当前轮次的上下文、思考、步骤、工具、审批和提问状态直接渲染到助手消息气泡中。流式回复期间，这些过程行显示在尚未完成的助手文字之前；还没有助手消息时，使用同样的助手气泡追加一个临时过程行。移除独立的可展开面板及其交互。

## Alternatives considered

**保留可展开的尾部面板。** 放弃，因为它隐藏了处理过程与用户正在等待的答案之间的关系。

**创建第二条只显示过程的对话流。** 放弃，因为它会重复记录，并丢失过程相对于助手回复的 Web 事件顺序。

**把生命周期行持久化成普通消息。** 放弃，因为它们是观察性的会话事件，不是持久化的用户或助手消息。

## Consequences

手机端现在显示一条助手样式的连续流：实时过程行先变化，然后在同一个气泡中显示助手的流式回复。过程行仍然只读；每行对详情设置视觉高度限制，让输入栏保持可用，同时保留用户要求的 Web 等价过程视图。

## Testing

本次改动执行手机端 TypeScript 类型检查、聚焦协议与 mobile-access 测试、JS bundle 生成、APK 签名校验、安装、应用启动和无崩溃 logcat 检查。
