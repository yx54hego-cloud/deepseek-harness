# Agent Note: A separate authenticated carrier for the mobile companion

Status: implemented

English | [中文](2026-08-14-mobile-companion-carrier.zh.md)

## Problem

The browser carrier is intentionally a local product surface. Its authority fence prevents browser confused-deputy attacks but is not user authentication, and its API contains remote-code-execution-grade methods. Publishing that carrier to a phone would enlarge both network reachability and method authority. The requested phone surface needs only existing Session discovery, archived-id filtering, text and durable-image history, live conversation updates, model selection, and text or raster-image follow-ups into the same Session; it does not need workspace contents or mutations, terminals, general documents, Git, settings, approvals, collaboration, or a second conversation implementation.

## Decision

Add `dsh-host-mobile-access` as a separate optional carrier over the existing transport-independent `ctx.apiProxy`. `dsh web --mobile` activates its own all-interfaces WebSocket listener while the browser server remains loopback-only. The carrier accepts only `session.list`, `session.history`, `session.models`, `session.selectModel`, `session.attachment`, queue-mode `session.prompt` containing text and the four existing raster-image formats, and the carrier-local `mobile.archivedSessions` read that projects only archived Session ids from `workspace.list`. It forwards Session events plus title, status, archive-set, and host lifecycle frames needed by that surface. The Host validates the allowlist and payload restrictions before handing accepted Session requests to the existing fetch carrier, so a modified phone cannot escape the same limits or read workspace contents. The default encrypted-frame ceiling is 16 MiB; the phone caps aggregate image bytes at 5 MiB so base64 expansion and the request envelope remain inside it.

Pairing adopts the compact pattern used by Orca's MIT-licensed mobile implementation: `dsh://pair?code=<base64url JSON>` carries a direct endpoint, persistent host id, bearer token, and pinned Curve25519 public key. The host identity lives in an owner-only file under `$DSH_HOME/mobile`. The host advertises the IPv4 address selected by the operating system's default route; an explicit `advertiseHost` remains authoritative, and unresolved multi-adapter ambiguity fails startup instead of printing an unusable QR. Every socket uses a fresh phone key pair, derives a Curve25519 shared key, sends the bearer token only inside the encrypted authentication frame, and protects subsequent JSON with XSalsa20-Poly1305. Handshake deadlines, input and request ceilings, outbound buffering limits, socket ownership, and abort-driven event teardown belong to the carrier lifecycle.

The Expo app is a native companion rather than a responsive copy of the Web UI. It stores one pairing in the operating system secure store, reconnects with bounded backoff, and bounds socket opening plus encrypted authentication with one connection deadline. Its generated Android manifest permits the carrier's direct `ws://` LAN socket while retaining React Native's legacy system Back dispatch; application frames remain authenticated and encrypted. A valid scan immediately leaves the camera surface; a failed connection retains the pairing and presents the advertised endpoint with Retry and Forget computer actions. Reconnection refetches Session list, archived ids, the latest six model messages, and the selected Session's model directory as baselines. The conversation remains the base surface under a modal navigation drawer. The drawer derives display-only workspace groups from Session working directories and repeats recent Sessions without requesting workspace rows. A newly opened conversation positions the transcript at its latest message after the native list has completed its first layout; paging six earlier messages retains the visible position. The composer renders the Host-selected model, refreshes the same provider-grouped directory as the browser selector without disabling cached rows during that refresh, and awaits `session.selectModel` before presenting a new selection. Its plus control opens the operating-system picker for PNG, JPEG, WebP, and GIF images, stages removable previews, sends bytes through the existing Host attachment admission path, and fetches authorized durable image refs for history/live transcript rows. Text, staged images, and the selected model remain intact when a request fails; submission has no automatic retry so an ambiguous disconnect cannot duplicate a prompt. RPC error codes and messages remain visible in the composer diagnostic so provider entitlement, image modality, and session-liveness failures are distinguishable. Brand and product glyphs come from the approved mobile composition instead of a generic icon font; their visible dimensions remain independent from platform-sized touch targets. New Session creates a real Host session and opens it immediately. Drawer search and sort are local projections, and workspace groups can be expanded or collapsed independently; workspace creation remains disabled because it belongs to the Web side. General documents and voice capabilities remain reserved without expanding carrier authority.

This decision complements rather than supersedes the [browser trust boundary](2026-07-28-api-browser-trust-boundary.md): that record still owns confused-deputy defense for local `/api` routes, while this record owns authentication and encryption for a different network listener. The [Web transport layering](2026-07-24-web-config-tree-boot-and-transport-layering.md) remains authoritative for the shared gateway and browser carrier split.

## Alternatives considered

- **Bind the existing Web server to the LAN and reuse its browser client.** Rejected because the authority fence is not authentication and the full browser API is much broader than the requested phone capability.
- **Build a second mobile session backend.** Rejected because two list, history, prompt, and event implementations would diverge; `ctx.apiProxy` already owns the business semantics and durable log path.
- **Start with an Internet relay.** Rejected because relay identity, discovery, TLS, account recovery, push, and operational ownership are independent product decisions. Direct LAN access proves the companion workflow without pre-deciding them.
- **Copy Orca's workspace and terminal application.** Rejected because those surfaces contradict the requested narrow forwarding role and would authorize more host capability than the phone needs.

## Consequences

- A phone prompt becomes the same durable `user/message` observed by the desktop browser, and live assistant events converge on both clients.
- Archived Sessions stay hidden after reconnect and disappear when another client archives them; the phone never receives workspace rows.
- A conversation initially transfers six model messages and fetches older pages on demand. One long message may still contain many durable streaming events.
- Mobile activation is explicit and does not weaken the default browser binding or expose browser routes.
- Anyone who can scan the active pairing QR receives the persistent mobile capability until the identity file is rotated. The first version documents manual rotation and one stored host rather than presenting incomplete device management.
- Direct `ws://` traffic discloses connection metadata but not authenticated application plaintext. Internet transport, multiple paired-device revocation, Markdown/tool presentation, general documents, interactions, and background notification remain separate work.
- Real-Loader tests cover authentication, encrypted RPC, archive-set projection and events, model directory and selection, image prompt admission, wrong-token rejection, and teardown; the mobile projection tests cover pairing parsing and streamed-to-final text convergence.
